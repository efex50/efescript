# efevm

`efevm` is the register-based bytecode VM for efescript, roadmap item E1 (the spec is `SPEC.md`, draft 6). It is the only VM efescript runs on: the old `.efe` VM was removed (roadmap E3.6), and the `.efa` assembler (E2) targets `efevm`. It has a verifier that runs at load time, a binary `.efvm` codec, a fiber-based interpreter with an instruction budget, and no I/O: everything outside the VM is a host function supplied by the embedder through a `HostRegistry`, which is also the source of the API index (`API_INDEX.md`). **Used by: `efescript` (assembler, disassembler, `run`/`build`/`api`/`lsp`/`debug` CLI, std host) and `efeengine-core` (`engine::scripting`, the engine's host functions and mods).**

## Main concepts
- **Value types and functions** (`types.rs`): `ValType` is `I32, I64, F32, F64` (bytes 0-3 in the binary format). `FuncType { params, results }`. `Limits` (`types.rs:46`) holds the embedder caps: `max_memory_pages` (default 1024, 64 MiB), `max_call_depth` (4096), `max_registers` (262144, per fiber), `max_fibers` (256).
- **Opcodes** (`op.rs`): `Op` is `#[repr(u16)]`, and every variant has an explicit permanent number. The `define_ops!` macro generates the enum, `Op::ALL`, `from_u16`, `name()` and `shape()` from one table. The header comment in `op.rs` gives the ranges: 0x000-0x00F control, 0x010-0x01F constants/moves/select/globals/memory management, 0x020-0x03F i32, 0x040-0x05F i64, 0x060-0x07F plain loads/stores, 0x080-0x09F narrow loads/stores, 0x0A0-0x0BF f32, 0x0C0-0x0DF f64, 0x0E0-0x0FF width conversions, 0x100-0x11F conversions. The `hot_ops_are_one_byte` test checks that the common ops fit in one LEB byte. `Op::is_terminator` covers `ret`, `jmp`, `br_table` and `unreachable`.
- **Shape** (`op.rs`): the operand layout of each op (`D`, `DA`, `DAB`, `Select`, `Load`, `Store`, `ABC`, `Jmp`, `Br`, `Call`, `CallIndirect`, `Ret`, and others). The binary decoder, the verifier and the builder all dispatch on it.
- **OPCODES.md**: `opcodes_markdown()` (`op.rs`) renders the table. `cargo test -p efevm --test opcodes` rewrites `OPCODES.md` when its content differs. The `opcodes_md_lists_every_op` test checks that every mnemonic and hex code is present.
- **Inst** (`module.rs:26`): a fixed 16-byte `{ op, a, b, c: u32 }`. The field mapping is in the doc comment at `module.rs:8-24`. In short: `D` uses `a=d`; `DA` uses `a=d, b=a`; `DAB` uses `a=d, b, c`; `ConstI64`/`ConstF64` put the low 32 bits in `b` and the high 32 bits in `c`; `Select` uses `a=d, b=cond, c = ra | rb<<16`; `Load` uses `a=d, b=base, c=offset`; `Store` uses `a=src, b=base, c=offset`; `Jmp` uses `a=L`; `Br` uses `a=reg, b=L`; `BrTable` uses `a=reg, b=index into br_tables`; `Call` uses `a=func, b=base`; `CallIndirect` uses `a=type, b=reg, c=base`; `Ret` uses `a=base`. Unused fields must be 0, and the verifier rejects anything else (`NonZeroUnusedOperand`).
- **ModuleData vs Module** (`module.rs`): `ModuleData` is the plain, unverified form (types, imports, functions with `code` and `br_tables`, `table`, `memory`, `globals`, `exports`, `data`, `names`, `lines`, `api`, `interface`: section 13, what a mod provides, SPEC 9.2, and `events`: section 14, the script events the module sends or reads, SPEC 9.3; an event's id is its index there, and `event_namespaces()` lists their namespaces for the allow-list check). `Module` wraps it in an `Arc` and exists only after `verify::verify` has passed (`Module::new`). `Module::decode` is `binary::decode` followed by `Module::new`, and `export_func` / `export_global` look up exports by name.
- **Builders** (`builder.rs`): `ModuleBuilder::add_type` deduplicates function types. `import` must come before any function (otherwise `BuildError::ImportAfterFunction`). `declare_func` and `define` allow forward references and mutual recursion, and `add_func` does both at once. `FunctionBuilder::new(nregs)` has typed emitters (`op0`..`op3` check the shape, and `const_*`, `load`, `store`, `call`, `ret` and so on are direct). Labels come from `new_label()` and `bind(l)`, and are stored as label ids. `finish_unverified` resolves each id to an instruction index (`resolve`, `builder.rs:199`), and `finish` then verifies. The first builder error is kept and reported at finish. `loc(file, line, col)` records line entries, and `file(name)` interns file names. `event_ref(namespace, name, payload)` adds a section 14 entry and returns its event id (an identical entry is reused).
- **Verifier** (`verify.rs`): `verify()` returns the first failure as `LoadError::Verify { func, inst, error }`. `VerifyError` has one variant per rule: index ranges (types, functions, globals, table, exports, names and lines), register numbers `< nregs`, label and `br_table` ranges, call and return windows (`base + max(P, R) <= nregs` for calls, `base + nresults <= nregs` for `ret`), `nregs >= params`, `global.set` only on mutable globals, 32-bit global initializers with no upper bits, memory `min <= max`, data segments inside the initial memory, a terminator as the last instruction (`MissingTerminator`), and zero unused operand fields. Duplicate export names are rejected too. Section 13 (`interface`) is checked by `verify_interface` against SPEC 9.2 rules 1-9, all reported as `VerifyError::Interface { what, reason }` naming the provide, struct, event or scratch region. Section 14 (`events`) is checked by `verify_events` (SPEC 9.3) as `VerifyError::Events { what, reason }`. The verifier is what makes "registers are untyped, memory is bounds-checked" safe (SPEC section 8).
- **Binary format** (`binary/`): `decode.rs` reads a 10-byte header (`EFVM`, version `2`, CRC-32 of the rest, checked before anything else: `BadChecksum`), then sections in strictly increasing id order from 1 to 14. Ids 128 and above are skipped as custom sections, and any other id is rejected. Each section's payload must be consumed exactly (`finish`, otherwise `SectionSizeMismatch`). Every vector count is checked against the bytes that remain before anything is allocated (`Reader::count`, `CountTooLarge`). Register operands must be at most `0xFFFF`. Unknown opcodes are reported with their number (`UnknownOpcode`). The functions and code counts must match (`FunctionCodeMismatch`). `leb.rs` implements the rule from SPEC section 9.1: a LEB is over-long if it has more than `ceil(bits/7)` bytes, or if the final byte sets bits the type cannot hold. `encode.rs` writes the same layout, omits empty sections and fills in the checksum last (`binary::seal`, also public for hand-built bytes), so `decode(encode(m)) == m`. Section 13 (`interface`) adds `BadApiType` and `BadPrim`; the vectors of sections 13 and 14 grow by push rather than being pre-allocated from counts. Decode errors come back as `LoadError::Decode { offset, error }`.
- **Memory** (`memory.rs`): one `Vec<u8>` sized in 64 KiB pages. `Memory::new` returns `None` if `min > max` or the allocation fails. `range()` uses checked arithmetic, so an address past the end or an overflowing `addr + len` returns `Trap::OutOfBounds`. `load::<N>` and `store::<N>` take `base + off`. `copy` checks both ranges before moving and handles overlap. `grow` returns the old page count, or `None` on failure. The effective maximum is `min(module max, embedder cap)`, and it is applied in `Instance::new` (`instance.rs:87`).
- **Host registry** (`api/registry.rs`): `HostRegistry<H>` is the only way to make a host function callable. `define_namespace(name, version, owner, doc)`, `register(HostFn, f)` / `replace` (hot reload), `register_type(StructDesc)`, `register_event(EventDesc)` / `replace_event` and `unregister_owner(owner) -> Result<usize, _>` (which also removes the owner's events and refuses while another owner's function or event uses one of its structs) enforce the rules of e3-design.md section 2 (one `RegistryError` variant per rule). The typed form is `Fn(&mut Caller<H>, &Args, &mut Results) -> Result<HostOk, Trap>`; the registry wraps it once into the raw `HostFunc<H>` the interpreter calls, so `interp.rs` is unchanged. `Args` reads by logical parameter index with type checks (`i32`, `i64`, `f32`, `f64`, `bool`, `entity`, `ptr`, `str`/`bytes` -> `GuestSlice`; `raw()` for the slots); `Results` has the matching `set_*`; nothing panics. `imports()` snapshots functions, namespace versions, events (with payload struct name and size) and the index hash into an `Imports`; `index()` returns the same table as an `ApiIndex` (`game` from `set_game`). There is no second table: the index test is `imports().names()` vs `index()`.
- **API index** (`api/index.rs`, `api/json.rs`): `ApiIndex { game, namespaces, types, functions, events }` is plain data (format version 2; the reader accepts only 2). `to_json()` writes the exact `API_INDEX.md` layout (sorted, two-space indentation, final newline), `hash()` is FNV-1a 64 over that text without the `game`/`hash` lines, and `from_json()` parses with a hand-written reader (depth limit 64, full `\u` escapes with surrogate pairs, strict number syntax), checks `format`, `version`, every `signature`, the names and layouts (`validate()`), and the hash (accepted if it matches either the raw file body or the canonical rewrite, so reformatted files and keys from newer writers both work).
- **Imports and Caller** (`imports.rs`): `Imports<H>` maps `(namespace, name)` to `(FuncType, HostFunc<H>)` and carries namespace versions, the registered events (`event`, `events`) and the index hash; it has no public adder (the only producer is `HostRegistry::imports()`). `names()` lists what is callable; `check_module(&Module)` returns every `LinkError` at once, including `UnknownEvent` and `EventPayload` for section 14 references. `Caller` gives access to `&mut H`, memory (`read`, `write`, `memory_mut`, and the checked helpers `read_bytes`, `read_str`, `write_bytes`, `read_struct`, `write_struct`, `read_u32/u64/f32/f64`, `write_*`: negative pointers or lengths are `OutOfBounds`, nothing allocates before the range is checked) and globals (`global`, `set_global`, which respects the mutable flag). `HostOk::Continue` continues execution, and `HostOk::Yield` writes the results and then suspends the fiber. A host function cannot call back into the VM (SPEC section 7).
- **Instance** (`instance.rs`): `Instance::new(&module, &imports, limits)` returns the first error of `Imports::check_module` (namespace versions of section 12: `UnknownNamespace`, `NamespaceVersion`; then each import by name and exact `FuncType`: `MissingImport`, `ImportTypeMismatch` with both signatures as text; then each section 14 event: `UnknownEvent`, `EventPayload`), allocates memory, copies data segments in, and initializes globals. `infos` holds one `FuncInfo { np, nr, nregs, canon }` per function index, and `canon` is a structural type id used for `call_indirect`. The `spawn(export, args)` and `spawn_func(index, args)` methods create a fiber with the arguments placed in `r0..`. Imports cannot be spawned (`ImportEntry`). `set_global` ignores the mutable flag, because it is the embedder's API.
- **Fibers** (`instance.rs`): a `FiberId { index, generation }` indexes a slot in `slots`. Freed slots go onto `free`, and their generation is bumped, so stale ids are rejected (`resume` returns `Trap::Host("invalid fiber")`). `FiberStatus` is `Ready` (spawned, or stopped by `OutOfBudget`), `Suspended` (after `yield` or a host yield), `Done`, or `Trapped(Trap)`. `resume(fiber, host, budget) -> Exit` and `resume_counted(...) -> (Exit, u64)` also return the number of instructions executed (not budget units); `resume_units(...) -> (Exit, u64)` returns the budget units consumed (instructions + bulk extra + debt paid, at most `budget`). `call(export, args, host, budget) -> Result<Vec<u64>, CallError>` spawns, resumes once and always removes the fiber; `CallError::Trap` carries the trap, location and backtrace. `results(fiber)` is valid only for a `Done` fiber. When a fiber finishes or traps, its register, call and scratch stacks are freed (`fiber_stack_capacity`, doc-hidden, shows this) and only its results, status and trace are kept. The fibers share memory and globals, but each has its own registers and call stack. The VM never switches fibers by itself.
- **Budget** (`interp.rs`, `run`): each instruction costs 1 unit, including `call`, host calls, `yield`, and an instruction that traps. `memory.copy`/`memory.fill` cost `1 + len/256` and `memory.grow` costs `1 + pages*256` (saturating, charged even if the grow fails; a trapping bulk op costs 1). The `charge!` macro handles the extra cost only inside those three ops: if it exceeds the budget left, the excess is stored in `Stack::debt` and the run returns `OutOfBudget`; `resume_counted` pays the debt first at resume entry (SPEC "Changes from draft 2"). When the budget reaches 0 before the next instruction, the loop saves `func`, `pc` and `fp` and returns `OutOfBudget`. A budget of 0 executes nothing.
- **Register stack and frames** (`interp.rs`): a `Stack` holds `regs: Vec<u64>` (all activations of one fiber, contiguous), `frames: Vec<Frame>`, the current `func`, `pc` and `fp`, and `results`. A `Frame { func, pc, fp, base }` records the return position, the caller's frame base, and `base`, the caller's window where the results go. Each activation's registers are `regs[fp..fp+size]`, with `size = max(nregs, params)`. Parameters start at `r0`, and the rest start at zero.
- **Calling convention** (`interp.rs`, `Op::Call`, `Op::Ret`): for a `call f, base`, the callee's new frame starts at the end of the caller's frame (`new_fp = fp + f.len()`). The `P` arguments are copied from `base` into `new_fp`. `ret base` copies `R` results from `base` into the caller's `base`, truncates `regs` back to the callee's `fp`, and restores the caller's `func`, `pc` and `fp` from the popped frame. Registers outside the window are untouched. The call depth is checked against `max_call_depth` and the total against `max_registers`, and both produce `Trap::StackOverflow`. For `call_indirect`, the table entry `g` gets the same frame setup, and the type check compares `canon` ids (`IndirectCallTypeMismatch`).
- **Host calls in the loop** (`interp.rs`): a call whose target index is below the import count builds a `Caller` over `host`, `memory`, `globals` and `gmut`. It passes the argument slice, writes results into a scratch buffer, and copies them into the window on success. `HostOk::Yield` then returns `Exit::Yield`, and `Err(t)` traps the fiber.
- **Traps and exits** (`trap.rs`): `Trap` has `OutOfBounds`, `DivideByZero`, `IntegerOverflow`, `InvalidConversion`, `Unreachable`, `StackOverflow`, `UndefinedElement`, `IndirectCallTypeMismatch` and `Host(String)`. `Exit` has `Done`, `Yield`, `OutOfBudget` and `Trap(Trap)`. A trapped fiber stays dead, but the instance remains usable (`instance.rs` test `host_yield_and_trap_and_link_errors`).
- **Integer and float semantics** (`interp.rs`): i32 results are written zero-extended. Shifts and rotates use the count modulo the width. `div_s` of `MIN / -1` traps with `IntegerOverflow`, and `rem_s` of `MIN % -1` is 0. The trapping truncations (`t_i32_f32_s` and so on) return `InvalidConversion` for NaN and `IntegerOverflow` when out of range. The saturating forms never trap. `fmin`/`fmax` return NaN if either input is NaN, and handle signed zeros. `nearest` uses `round_ties_even`.

## How to run
- Tests: `cargo test -p efevm`.
- Benchmark: `cargo run -p efevm --release --example bench`, with an optional iteration count argument. `examples/bench.rs` constants: default 100 000 000 iterations, `REPS = 5`, resume budget 10 000, target 10 ns per instruction.
- Regenerate the opcode table: `cargo test -p efevm --test opcodes`. This rewrites `OPCODES.md` if it differs.
- wasm check: `cargo check -p efevm --target wasm32-unknown-unknown` (with the target installed; otherwise `-Z build-std=panic_abort,std` on nightly).

## Notes
- Diagnostics and host context: `Instance::trap_location` / `Instance::backtrace` give the trapping `(func, inst)` and the call stack of a trapped fiber (join them with the names and lines sections); `Caller::fiber()` tells a host function which fiber is calling.
- Debugger hooks: for a `Ready`/`Suspended` fiber, `fiber_location` (next instruction), `fiber_registers` (current frame) and `fiber_backtrace`; `resume(fiber, host, 1)` executes exactly one instruction (tested in `tests/api.rs`).
- Section 12 `api` (`ModuleData::api: Option<ApiRef { hash, namespaces }>`, `ModuleBuilder::api_ref`) records the index a module was assembled against; the verifier rejects invalid or duplicate namespace names there.
- `src/instance.rs` has an `#[ignore]`d `bench_counting_loop` unit test. `examples/bench.rs` is the benchmark that is run in practice.
- `Instance::new` maps a data-segment write failure to `LinkError::MemoryTooLarge`. The verifier's `DataOutOfRange` check should make that path unreachable.
